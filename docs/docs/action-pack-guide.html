动作包开发指南

动作包通过 manifest.json 声明一组动作，注册到 Flow 编辑器作为可视化积木。支持 Rust 和 Lua 两种执行器。

Exero V0.4.0-Beta5 · 动作包（pack_type: action）开发文档

快速入门

5 分钟创建一个 Hello World 动作包。

1. 创建目录结构

my-action-pack/
├── manifest.json
└── scripts/
    └── hello.lua

2. 编写 manifest.json

{
  "id": "my-action-pack",
  "version": "1.0.0",
  "name": "我的动作包",
  "description": "Hello World 示例动作包",
  "author": "Your Name",
  "exero_api_version": "0.4.0",
  "pack_type": "action",
  "actions": [
    {
      "id": "hello",
      "executor_type": "lua",
      "executor_id": "scripts/hello.lua",
      "label": "Hello",
      "category": "lua",
      "icon": "Code",
      "default_params": { "name": "World" },
      "ports": {
        "inputs": [{ "id": "trigger", "position": "top" }],
        "outputs": [{ "id": "done", "position": "bottom" }]
      },
      "summarize_template": "Hello {name}",
      "description": "向指定对象打招呼",
      "permissions": [],
      "params": [
        {
          "name": "name",
          "label": "称呼",
          "type": "string",
          "default": "World",
          "options": [],
          "required": false
        }
      ]
    }
  ]
}

3. 编写 Lua 脚本

-- scripts/hello.lua
local name = args.name or "World"
exero.log("Hello, " .. name)
exero.notify("info", "Hello", "Hello, " .. name)
exero.set_result({ message = "Hello, " .. name })

4. 打包安装

将目录压缩为 .exero-pack（zip 格式），在「设置 → 扩展包」中导入安装。安装后 Flow 编辑器动作目录会出现 "Hello" 积木。

Manifest 字段参考

ExtensionPackManifest（根结构）

字段类型必填说明
idstring必填扩展包唯一标识（建议小写 + 连字符）
versionstring必填SemVer 版本号（如 1.0.0）
namestring必填显示名（中文）
descriptionstring可选描述
authorstring可选作者
exero_api_versionstring必填所需 Exero API 版本（当前 0.4.0）
pack_typestring可选动作包为 action（默认）
rust_librarystring可选Rust .dll 相对路径（仅 Rust 动作需要）
actionsActionManifest[]可选动作声明列表
sidebarSidebarManifest不支持侧边栏入口（仅插件可用）
uiUiManifest不支持插件 UI 声明（仅插件可用）

ActionManifest（动作声明）

字段类型必填说明
idstring必填动作唯一标识（扩展包内唯一）
executor_typestring必填rust 或 lua
executor_idstring必填Rust：ActionType 枚举名；Lua：脚本相对路径
labelstring必填动作显示名
categorystring必填类别：app/media/system/notification/control/lua
iconstring可选lucide-react 图标名（默认 Code）
default_paramsobject可选创建节点时的初始参数
portsPortsManifest可选端口配置
summarize_templatestring可选参数摘要模板（如 {path}）
descriptionstring可选动作描述
permissionsstring[]可选Lua 沙箱权限声明（仅 Lua 动作）
paramsScriptParam[]可选Lua 脚本参数定义（仅 Lua 动作）

PortsManifest（端口配置）

{
  "inputs": [{ "id": "trigger", "position": "top" }],
  "outputs": [{ "id": "done", "position": "bottom" }]
}
字段类型说明
inputsPortManifest[]输入端口列表
outputsPortManifest[]输出端口列表

PortManifest（端口）

字段类型必填说明
idstring必填端口唯一标识
positionstring必填top/bottom/left/right
labelstring可选显示名（用于 IfElse 的 then/else 标签）

ScriptParam（Lua 参数定义）

字段类型必填说明
namestring必填参数名（Lua 通过 args.xxx 访问）
labelstring必填显示标签
typestring必填string/number/boolean/select
defaultany可选默认值
optionsstring[]可选select 类型的可选项
requiredboolean可选是否必填（默认 false）

Lua 动作开发

Lua 动作通过 LuaJIT 沙箱执行，提供 5 个核心 API。

核心 API

exero.log(msg)

写日志到 Exero 日志系统。

exero.log("开始执行任务")

exero.notify(level, title, body)

发送应用内通知。level："info" / "warning" / "error"

exero.notify("info", "任务完成", "已处理 10 个文件")

exero.get_var(name, global?)

读取变量。默认局部（当前 Flow 上下文），global=true 读全局变量（跨动作链共享）。

local count = exero.get_var("count")
local total = exero.get_var("total", true)

exero.set_var(name, value, global?)

设置变量。默认局部，global=true 设置全局。

exero.set_var("count", count + 1)
exero.set_var("total", 100, true)

exero.set_result(value)

设置脚本返回值，作为 ActionResult.output。

exero.set_result({ status = "ok", data = { 1, 2, 3 } })

参数访问

通过 args 表访问 manifest params 声明的参数：

local name = args.name       -- string 参数
local count = args.count     -- number 参数
local enabled = args.enabled -- boolean 参数
local mode = args.mode       -- select 参数

可用标准库

严格沙箱下可用：string / table / math / os.date / os.time / os.clock。

需要 os.execute / io 等宽松权限时，在 manifest permissions 中声明：

"permissions": ["io", "os.execute"]

完整 Lua 示例

-- scripts/counter.lua
-- 演示变量系统：跨动作链累加计数器
local increment = args.increment or 1
local reset = args.reset or false

if reset then
    exero.set_var("counter", 0, true)
    exero.log("计数器已重置")
else
    local current = exero.get_var("counter", true) or 0
    local new_value = current + increment
    exero.set_var("counter", new_value, true)
    exero.log("计数器: " .. new_value)
end

exero.set_result({ counter = exero.get_var("counter", true) })

Rust 动作开发

Rust 动作分两种模式：

模式 1：内置 ActionType（无需 .dll）

如果动作对应 Exero 内置的 ActionType，直接在 manifest 声明，无需编写 Rust 代码：

{
  "id": "launch-notepad",
  "executor_type": "rust",
  "executor_id": "LaunchProgram",
  "label": "启动记事本",
  "category": "app",
  "icon": "AppWindow",
  "default_params": { "path": "notepad.exe" },
  "ports": {
    "inputs": [{ "id": "trigger", "position": "top" }],
    "outputs": [{ "id": "done", "position": "bottom" }]
  },
  "summarize_template": "{path}"
}

内置 ActionType 列表

executor_id说明category
LaunchProgram启动程序app
KillProcess结束进程app
SetVolume设置系统音量media
MuteVolume静音/取消静音media
Shutdown关机system
Restart重启system
Sleep休眠system
Lock锁屏system
Notify系统通知notification
Delay延时control

模式 2：自定义 .dll 动作

如果需要自定义逻辑，编写 Rust .dll。详见 插件开发指南（动作包也可使用 .dll，但通常推荐用插件形态）。

动作包使用 .dll 时，manifest 需声明 rust_library：

{
  "id": "my-action-pack",
  "pack_type": "action",
  "rust_library": "my_pack.dll",
  "actions": [
    {
      "id": "custom-action",
      "executor_type": "rust",
      "executor_id": "custom-action",
      "label": "自定义动作",
      "category": "lua",
      "icon": "Code",
      "default_params": {},
      "ports": {
        "inputs": [{ "id": "trigger", "position": "top" }],
        "outputs": [{ "id": "done", "position": "bottom" }]
      },
      "summarize_template": "Custom"
    }
  ]
}

打包与发布

打包

将扩展包目录压缩为 .exero-pack（zip 格式），要求 manifest.json 位于压缩包根目录。

# PowerShell 打包示例
Compress-Archive -Path my-action-pack\* -DestinationPath my-action-pack.exero-pack -Force

发布到市场

  1. 将 .exero-pack 文件放入仓库 Market/action-packs/ 目录
  2. 运行 scripts/build-packs.ps1 重新生成 market-index.json
  3. 推送到 GitHub 仓库
# 项目根目录执行
powershell -ExecutionPolicy Bypass -File scripts\build-packs.ps1

安装方式

  • 市场安装：Exero 内「扩展市场」页面直接安装
  • 本地导入：「设置 → 扩展包」导入本地 .exero-pack 文件
